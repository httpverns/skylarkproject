## Architecture Decisions

### Why This Approach?
1. **Standalone JavaScript**: No complex build pipeline or transpilation needed
2. **Express Dev Server**: Simple, easy to understand, serves both game and API
3. **Data-Driven Design**: All game content goes into data files, not hardcoded
4. **FLARE Compatibility**: Folder structure and naming follows FLARE Engine conventions
5. **Incremental**: Each phase adds one complete system without breaking existing functionality

### Why Canvas Instead of FLARE Engine Directly?
- **Faster iteration** during Phase 1-2 for core systems
- **Full control** over rendering and game loop
- **FLARE compatibility** maintained through data structures
- **Future migration path** to pure FLARE or FLARE integration in later phases
